# PERF-001: лишняя работа в обновлении леса, сквозняков и снежных следов

База: `de20db3bb8883af6ade9afb5bb418b708afd9d71`.
Задача ограничена вычислениями: настройки графики, количество объектов, геометрия,
дальности, частота физики, тепловая модель и механика снега не меняются.
Дом остаётся частью общего мира. Изменения записи диагностики и персонажа не входят в PR.

## Исправления

- При стриминге леса не отправляются заново одинаковые float32-матрицы и не
  пересчитываются bounds неизменившихся пространственных групп. Изменение матрицы,
  числа деревьев, рост буфера, рубка и удаление группы по-прежнему обновляют данные.
- В тепловой сетке соответствие ячеек для распространения сквозняка рассчитывается
  один раз при инициализации. Порядок обхода, float32-округления и коэффициенты
  сохранены. Предыдущий снимок поля копируется в повторно используемый буфер.
  Открытые/сломанные окна и двери продолжают задавать поток каждый кадр.
- При обновлении следов снега толщина подложки запрашивается один раз на точку
  и используется для чтения материала и записи пикселей. Было 23 067 запросов
  покрытия на полную плитку, стало 7 921. Данные переиспользуются только внутри
  одного refresh: изменение крыши/укрытия не оставляет устаревшего покрытия.
  Добавляется один буфер Float64 на renderer (~62 КиБ), а не на каждую плитку.

## Сравнение стоимости CPU

Production-сборки базы и кандидата, Chromium `/usr/bin/chromium`, ANGLE SwiftShader,
seed 42, 13:00, ясно, мир 3072 м. Вызовы RAF отключены до загрузки: это изолированные
синхронные вызовы подсистем после десяти прогревочных вызовов, **не FPS игры**.
Замеры выполнялись последовательно. Время в мс; абсолютные пики чувствительны
к JIT, GC и планировщику облачной машины.

| Сценарий | До, медиана / p95 | После, медиана / p95 | Суммарное время до → после |
|---|---:|---:|---:|
| Лес: 96 перемещений по 15 м туда/обратно около старта | 2,9 / 5,6 | 2,4 / 6,7 | 285,4 → 273,2 |
| Тепло: 300 обновлений по 0,2 игровой секунды, дверь открыта, окна разбиты | 1,9 / 8,1 | 1,5 / 4,8 | 992,0 → 625,2 |
| Следы: 60 полных обновлений плитки при снежном переносе | 9,7 / 18,3 | 5,0 / 19,2 | 642,6 → 398,0 |

Пики маршрута леса и p95 снежного refresh в этом прогоне не улучшились. Нельзя
объявлять все подёргивания устранёнными или переносить эти числа на GPU пользователя.
Отдельная проверка 3000 неизменившихся экземпляров леса в Node (100 повторов после
20 прогревочных) дала медиану 1,81 → 0,33 мс; это именно неизменившиеся группы,
а не весь forest.update и не FPS. Польза на маршруте меньше из-за остальных работ
по стримингу и меняющегося состава пограничных групп.

Повторить браузерное сравнение (Playwright должен быть доступен):

```sh
npm run build
CHROMIUM_PATH=/usr/bin/chromium node tests/perf-cost-browser.cjs "$PWD" /tmp/perf-result.json
```

Для старой версии выполнить те же команды в отдельном checkout базы, передав
актуальному скрипту путь к той сборке. Не запускать сравниваемые браузеры параллельно.

У обоих прогонов 20 снежных плиток, одинаковая FNV-контрольная сумма всех их
half-float данных `189246667`, 319 rigid bodies и 2085 colliders после маршрута.
Это подтверждает неизменность данных в данном сценарии, не заменяет визуальный QA.

## Проверки

- `npm run build`
- `node tests/thermal-equivalence.cjs`: точное совпадение всех массивов температур,
  влажности, сквозняков, инея, поверхностей и агрегатов с прежним распространением
  сквозняка при 40 изменениях состояния окон/дверей, включая длинные шаги времени;
  отдельно проверены все ячейки и отображение под наклонной крышей.
- `npm run test:forest-instances`: матрицы, bounds, тени, рост буфера, удаление и
  повторное заполнение, отсутствие повторных GPU updates неизменившихся групп.
- `npm run test:trails`: инкрементальный/полный результат, изменение укрытия,
  погода и rewind, количество запросов покрытия.
- `npm run test:snow`, `npm run test:snow-cover`, `npm run test:statics`,
  `npm run test:resting`, `npm run test:locomotion`.
