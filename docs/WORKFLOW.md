# Разработка и выпуск

Рабочая версия игры открывается по умолчанию в репозитории. Для новой задачи обновите основную ветку (`origin/HEAD`) и создайте от неё рабочую ветку. В pull request укажите изменения для игрока и результаты проверок. После слияния рабочую ветку можно закрыть.

## Проверка кандидата

```bash
git fetch origin
git remote set-head origin --auto
node scripts/repo-check.mjs
npm ci
npm run build
npm test
```

Если основная ветка продвинулась, обновите свою ветку и повторите проверки затронутых механик. Для фиксированной базы можно передать `--base <SHA>`. Проверка истории отклонит кандидата без базы или обязательного предка. Команды браузерных проверок приведены в [README](../README.md#проверки).

## Выпуск на GitHub Pages

Проверьте итоговый коммит в собранной игре и согласуйте его с владельцем. В GitHub Actions вручную запустите **Release approved version**, выберите основную ветку репозитория и укажите полный SHA одобренного коммита. Тот же процесс позволяет выпустить ранее проверенный коммит из истории основной ветки.

Игра публикуется в корне сайта. По адресу `version.json` доступны SHA исходников и номер запуска Actions. В новых сборках старый адрес `/test/` перенаправляет в ту же игру и сохраняет параметры мира.
